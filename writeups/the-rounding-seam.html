Critical Worked example Doctrine 03 · 01 2026-08-12

The Rounding Seam

A credits-to-fiat conversion allows any authenticated user to mint value — because the debit path truncates at eight decimals while the credit path rounds half-up at two.

This is a constructed example, not a disclosure. The system described does not exist; it is assembled from the shape that this class of bug takes across every credits ledger I have modelled. It is here because the method is the point, and the method is easier to follow on a target I am free to describe completely.

Phase 00 — where the crowd is not

The target is a marketplace with a two-year-old bounty program. The disclosed record is thick with reflected XSS, subdomain takeovers, and a handful of IDORs on the profile API — all patched, all from the first six months. That record says two things. The obvious one: those classes are swept. The useful one: every disclosed report is a single-request bug against a single endpoint. Nobody in that record has modelled the ledger.

The changelog says a promotional credits balance shipped eleven weeks ago — users earn credits on referrals and can convert them to account balance at checkout. Value that enters through one door and leaves through another, in code that is under three months old. That is the target.

Phase 01 — the value model

Credits enter on referral, on promo redemption, and on refund of a credit-paid order. They move exactly one way: conversion to account balance. They leave through checkout. So the exit path runs credits → balance → order, and the conversion step is the only place two denominations meet.

Two denominations, two precisions. The credits endpoint reports eight decimal places. The balance endpoint reports two, in minor units, as an integer. Anywhere a system converts between precisions it must decide what happens to the remainder, and that decision has a direction. The assumption the developers made, written down as a hypothesis: the conversion is lossless, or it loses in the house's favour.

Phase 02 — attacking the assumption

The probe is arithmetic, not payload. Convert an amount whose remainder sits exactly on the rounding boundary and read both sides. At a published rate of 100 credits to 1.00 in balance, converting 0.005 credits should yield 0.00005 in balance — far below the smallest representable minor unit.

The credit side registered one minor unit. The debit side did not move at all. The server floors the credits debit to eight decimals — 0.005 credits is below its own precision after the internal rate multiplication, so it truncates to zero — while the balance credit rounds half-up to two decimals, and 0.00005 rounds to 0.0001, which the integer minor-unit column stores as 1. Value was created. The invariant is broken by one unit per call, and the call has no cost.

This is Doctrine 03 in its simplest form: a floor on the debit and a ceil on the credit. It reaches Critical rather than Low because the operation is unbounded and self-funding — nothing consumes credits, so the loop has no natural stop.

Phase 03 — verify the final state

The response said credited: 1, and the response is not evidence. Twenty 200s can apply once, and a credited field can be computed for display and never committed. Ground truth for a balance claim is the balance endpoint plus the ledger, read from a session that shares no cache with the one that made the request.

That last line is the finding. The ledger — the system's own record of every movement — sums to zero, while the balance it is supposed to describe reads 200 minor units. The two disagree, which means the balance is not derived from the ledger at all. The report writes itself from there: the invariant, the numbers, the two hundred calls that produced them, and nothing drained.

Why this is not a scanner finding

No payload was sent. No parameter was fuzzed. Every request in this writeup is well-formed, authenticated, and individually indistinguishable from normal use — a scanner would report a clean surface, and it would be right about everything it is capable of checking. The bug is not in a request. It is in the disagreement between two rounding decisions made in different files by different people, and the only way to reach it is to have written the value model down first.

Enumeration is a race against automation that never sleeps. Arithmetic correctness is a race against nobody.
